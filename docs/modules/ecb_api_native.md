# ecb_api_native: Native E-CoreBank API

> **Phase** 6  |  **Status** not started (after the compatible API is stable)  |  **Depends on** `ecb_platform`, `ecb_org`, `ecb_party`, `ecb_deposits`, `ecb_loans`

Generated parts of this document (the Fineract reference, API scope, data model and tests) come from
`parity/` inventories and are regenerated by `python parity/tools/module_docs.py build`. The rest is the
design and lives in `docs/modules/modules.json`. Overall approach: [design reference](../design/00-fineract-design-reference.md), [ADR-0001](../adr/0001-follow-fineract-design.md).

## 1. Purpose

Our own API under `/api/ecb/v1`, designed for new clients rather than for compatibility. It exists because the Fineract contract has quirks that we keep for parity but would not choose today. It calls the same domain modules and the same command pipeline, so there is one set of business rules behind both APIs.

## 2. Responsibilities

- A cleaner resource model with consistent pagination, ISO date strings and standard error objects
- OpenAPI-first definition with generated documentation
- The same authentication, tenant resolution, idempotency and maker-checker as the compatible API

## 3. Out of scope

- Duplicating business logic: it only adapts

## 7. Design to follow

- Both APIs go through the same commands; a rule fixed once is fixed for both
- Versioned from the start, with the backward-compatibility check Fineract applies to its own API

## 8. Build order

## 9. Contract tests

No Fineract test class applies: this API has no Fineract counterpart.

## 10. Acceptance criteria

Module-specific:

- Every native operation has a contract test and an equivalence test against the compatible API for the same command

Common to every module:

- Contract probe: every `must` read operation of this module passes against the oracle (status and response shape).
- Fineract's integration-test classes listed above pass, or each failure is recorded as a divergence with an ADR.
- Every state-changing operation goes through the command bus: validated, authorised, audited, idempotent, maker-checker aware.
- Every table has an Ecto migration in the tenant repo that matches the Fineract schema, and the cross-tenant isolation test covers the module.
- Money uses `Decimal` with an explicit currency and rounding rule; no floats.
- Dependencies point only at the modules in the header. `mix xref` finds no cycle or reverse dependency.
- `mix format`, Credo strict, Dialyzer and the module's tests pass; the module README and this document are updated.
