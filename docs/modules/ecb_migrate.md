# ecb_migrate: Migration from an existing Fineract database

> **Phase** 7  |  **Status** not started  |  **Depends on** `ecb_platform`

## 1. Purpose

A tool that brings an existing Fineract tenant into E-CoreBank. Because the schema follows Fineract's, migration is a verified data copy, plus the pieces that differ: the tenant registry entry, password handling and any version skew. It also produces a reconciliation report so a bank can prove nothing was lost.

## 2. Responsibilities

- Create a tenant database from our migrations and copy data table by table in dependency order
- Handle schema version skew by reading Fineract's Liquibase history
- Convert tenant connection details into a registry entry (no password stored)
- Reconciliation: row counts, sums of balances and journals, and per-account checks
- Dry run, resume after failure, and a cutover runbook

## 3. Out of scope

- Migration from systems other than Fineract

## 5. API scope

This module exposes no API; it is a command-line tool.

## 6. Data model

This module owns no tables. It reads a Fineract database and writes ours.

## 7. Design to follow

- Fineract moved from Flyway to Liquibase at 1.7 and refuses to start on a database older than 1.6; the tool applies the same rule and states the supported source versions
- Money and balances are compared by exact decimal equality, never by float
- The oracle itself is the test bed: migrate it and run the contract suite against the migrated copy

## 8. Build order

1. Schema version detection and the supported-version rule
2. Table copy in dependency order, with the reconciliation report
3. Dry run, resume, cutover runbook
4. Rehearsal on the oracle database

## 9. Contract tests

No Fineract test class applies. It is tested by migrating the oracle's own database and comparing the result.

## 10. Acceptance criteria

Module-specific:

- A migrated oracle database passes the same contract checks as the oracle
- Reconciliation shows zero differences in counts and balance totals

Common to every module:

- Contract probe: every `must` read operation of this module passes against the oracle (status and response shape).
- Fineract's integration-test classes listed above pass, or each failure is recorded as a divergence with an ADR.
- Every state-changing operation goes through the command bus: validated, authorised, audited, idempotent, maker-checker aware.
- Every table has an Ecto migration in the tenant repo that matches the Fineract schema, and the cross-tenant isolation test covers the module.
- Money uses `Decimal` with an explicit currency and rounding rule; no floats.
- Dependencies point only at the modules in the header. `mix xref` finds no cycle or reverse dependency.
- `mix format`, Credo strict, Dialyzer and the module's tests pass; the module README and this document are updated.
