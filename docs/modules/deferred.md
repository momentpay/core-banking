# deferred: Deferred features (not built in the first releases)

> **Phase** 8  |  **Status** parked by the cut list approved on 14 Nov 2026  |  **Depends on** none (a leaf of the dependency graph)

Generated parts of this document (the Fineract reference, API scope, data model and tests) come from
`parity/` inventories and are regenerated by `python parity/tools/module_docs.py build`. The rest is the
design and lives in `docs/modules/modules.json`. Overall approach: [design reference](../design/00-fineract-design-reference.md), [ADR-0001](../adr/0001-follow-fineract-design.md).

## 1. Purpose

Features in Fineract that a retail bank rarely needs and that the approved cut list parks: group and centre lending, meetings and calendars, collection sheets, share accounts and products, survey and poverty-index scorecards, the investor module for selling loan portions, SMS and email campaigns, and interoperation. Each deferred endpoint returns a documented 'not implemented' error and shows as skipped in the contract suite. This document keeps the scope, tables and tests together so any of them can be revived without rediscovery.

## 2. Responsibilities

- Nothing is built. This document is the record of what exists in Fineract and what reviving each feature would take

## 3. Out of scope

- Everything listed here, until a pilot bank asks for it

## 7. Design to follow

- Group and joint-liability lending depend on groups, centres, calendars and meetings together; reviving one means reviving all of them
- The investor module (asset externalisation) is event- and COB-driven and touches loans and accounting; it needs ecb_events and ecb_batch first
- If any of these is revived it becomes its own app with its own document, not an addition to an existing module

## 10. Acceptance criteria

Module-specific:

- Every deferred operation returns the documented 'not implemented' error
- The contract suite marks the corresponding classes skipped, with the reason

Common to every module:

- Contract probe: every `must` read operation of this module passes against the oracle (status and response shape).
- Fineract's integration-test classes listed above pass, or each failure is recorded as a divergence with an ADR.
- Every state-changing operation goes through the command bus: validated, authorised, audited, idempotent, maker-checker aware.
- Every table has an Ecto migration in the tenant repo that matches the Fineract schema, and the cross-tenant isolation test covers the module.
- Money uses `Decimal` with an explicit currency and rounding rule; no floats.
- Dependencies point only at the modules in the header. `mix xref` finds no cycle or reverse dependency.
- `mix format`, Credo strict, Dialyzer and the module's tests pass; the module README and this document are updated.
